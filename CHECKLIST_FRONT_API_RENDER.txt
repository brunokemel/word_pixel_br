    pinturas, carteira, protecoes, denuncias e pagamentos.

[ ] Criar um cliente HTTP central. Regras:
    - baseURL = VITE_API_URL sem barra final;
    - enviar Accept: application/json;
    - em POST, enviar Content-Type: application/json;
    - em rotas privadas, enviar Authorization: Bearer <access_token>;

    - nao usar credentials: "include": a API nao usa cookies de sessao;
    - aplicar timeout razoavel (30 a 90 s no primeiro acesso ao Render gratuito).

[ ] Gerar idempotencyKey com crypto.randomUUID() para cada NOVA acao mutavel.
    Em retry da MESMA acao, reutilizar a mesma chave. Nunca reaproveitar a chave
    para outro payload.

[ ] Tratar o formato de sucesso:
    { "ok": true, "data": { ... }, "request_id": "uuid-ou-id" }

[ ] Tratar o formato de erro:
    {
      "ok": false,
      "error": {
        "code": "CODIGO",
        "message": "Mensagem publica",
        "request_id": "uuid-ou-id"
      }
    }

[ ] Guardar/exibir error.request_id em mensagens de suporte e logs.
[ ] Nao assumir camelCase nas respostas: varios objetos vindos do PostgreSQL usam

5. ENDPOINTS REAIS PARA INTEGRAR
======================================================================

5.1 GET /map/chunks (PUBLICO)

[ ] Chamar:
    /map/chunks?bbox=minLng,minLat,maxLng,maxLat&zoom=0..22

    Exemplo:
    GET /map/chunks?bbox=-0.1,-0.1,0.1,0.1&zoom=10

[ ] Regras:
    - longitude entre -180 e 180; latitude entre -90 e 90;
    - minLng < maxLng e minLat < maxLat;
    - zoom inteiro de 0 a 22;
    - bbox pode abranger no maximo 256 chunks;
    - resposta limitada a 50.000 celulas;
    - limite HTTP atual: 120 consultas/minuto por IP/processo.

[ ] Resposta principal:
    data.chunks[] = {
      chunkX, chunkY,
      cells: [{ x, y, color, authorId, version, updatedAt }]
    }
    data.grid = { width: 65536, height: 32768, chunkSize: 64 }
    data.authoritative = true

[ ] O banco e esparso: celula ausente em chunks significa "nao pintada".
[ ] Debounce ao mover/zoom do mapa, cancelar requests antigos com AbortController e
    ignorar respostas obsoletas.
[ ] Dividir bbox grande em consultas menores para respeitar 256 chunks.

5.2 POST /pixels/paint (PRIVADO)

[ ] Headers: Authorization Bearer + Content-Type application/json.
[ ] Body:
    {
      "cellX": 32768,
      "cellY": 16384,
      "color": 3,
      "idempotencyKey": "UUID-V4"
    }
[ ] Validacoes: cellX 0..65535, cellY 0..32767, color inteiro 0..31.
[ ] Sucesso HTTP 200: data.pixel, com campos snake_case:
    cell_x, cell_y, chunk_x, chunk_y, color, author_id, version, updated_at.
[ ] Fazer optimistic UI somente se houver rollback ao falhar.
[ ] Limites: HTTP 30/10 s por usuario e token bucket adicional no banco.

5.3 POST /protections/quote (PRIVADO)

[ ] Body: { "originX": 32768, "originY": 16384 }
[ ] originX/originY precisam ser multiplos de 16 e dentro da grade.
[ ] A protecao e sempre 16x16 celulas.
[ ] Sucesso HTTP 201: data.quote:
    quote_id, origin_x, origin_y, price_credits, expires_at.
[ ] Mostrar preco e expiracao. A cotacao atual nao e enviada na compra; a compra
    recalcula o preco vigente no servidor.

5.4 POST /protections/purchase (PRIVADO)

[ ] Body:

5.5 GET /protections/:id (PRIVADO)

6. CODIGOS E COMPORTAMENTO DE ERRO
======================================================================

[ ] 400 VALIDATION_ERROR: corrigir payload/parametros; nao repetir automaticamente.
[ ] 400 CELL_NOT_LAND: avisar que celula/area nao e terrestre.
[ ] 401 UNAUTHENTICATED: renovar sessao uma vez ou pedir login.
[ ] 402 INSUFFICIENT_CREDITS: abrir fluxo de creditos (quando pagamento estiver pronto).
[ ] 403 FORBIDDEN: acesso negado.
[ ] 403 AREA_PROTECTED: area pertence a outro usuario; recarregar chunk.
[ ] 404 NOT_FOUND: recurso/rota inexistente.
[ ] 409 AREA_CONFLICT: atualizar protecoes/cotacao.
[ ] 409 IDEMPOTENCY_CONFLICT: a chave foi reutilizada com outro payload; gerar uma nova
    somente se for realmente uma nova acao.
[ ] 429 RATE_LIMITED: bloquear temporariamente, informar usuario e usar backoff.
[ ] 500 INTERNAL_ERROR: mensagem generica, logar request_id e permitir retry controlado.
[ ] Falha de rede/timeout: distinguir de erro HTTP e oferecer "Tentar novamente".

7. MAPA, COORDENADAS E TEMPO REAL
======================================================================

[ ] Grade: 65536 x 32768, origem no noroeste.
[ ] Converter longitude/latitude:
    cellX = min(65535, floor(((lng + 180) / 360) * 65536))
    cellY = min(32767, floor(((90 - lat) / 180) * 32768))
[ ] Chunk:
    chunkX = floor(cellX / 64)
    chunkY = floor(cellY / 64)
[ ] Protecao:
    originX = floor(cellX / 16) * 16
    originY = floor(cellY / 16) * 16
[ ] Paleta: manter mapeamento fixo de 32 cores para IDs 0..31.

[ ] Para Realtime, assinar public.pixel_cells no Supabase somente para a area/chunks
    visiveis, remover subscriptions antigas ao mover o mapa e atualizar por version.
[ ] Realtime e apenas sinal de atualizacao. Apos reconectar, trocar de area ou detectar
    perda de evento, refazer GET /map/chunks; a resposta HTTP e autoritativa.
[ ] Nao publicar eventos autoritativos pelo cliente.
